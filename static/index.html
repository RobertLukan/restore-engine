Restores

Watch queue health and per-VM restore progress. Pause stops new claims; in-flight jobs keep running.

Restore queue

How progress is measured

Live restore progress is the PVE restore task (data stream), not guest boot readiness. Live jobs report transferred X of Y (P%); normal jobs use PBS progress/zeroes. Est. wire ≈ virtual × fidx sparsity × compression (live) or (read − zeroes) × compression (normal). Pending jobs are queued largest-first within each batch (ad-hoc or one plan group) to shorten overall recovery time; plan groups still run in order.

Help

How restore-engine fits together — start with a location, then groups, then a plan.

Getting started

  1. Connect PBS and PVE

    Use the setup wizard (or Settings) to add Proxmox VE cluster(s) and PBS mounts. Test and verify before listing backups.

  2. Create a recovery location

    A location is where restores land: nodes, storage per node, VMID mode (normal vs DR), network isolation, and default power-on / QGA behavior.

  3. Define inventory groups

    Groups select which VMs belong together using VMIDs, ranges, name patterns, and/or tags. You can also save a Backups selection as a group.

  4. Build a recovery plan

    A plan orders groups onto a location. Run Check for readiness, Run for production failback, or Drill for a teardown exercise.

  5. Watch restore progress

    Ad-hoc restores from Backups and plan jobs both appear under Restores. Pause the queue, tune concurrency, and open job details for logs.

  6. Clean up restored guests

    After a drill or inspection, use Cleanup to destroy one batch at a time. Destructive — enable under Settings first.

  7. Prove recoverability

    Enable an Assurance policy, run Assure now, then review evidence on Compliance. That path does not replace Plans → Run for real failback.

Concepts

Run vs Drill vs Assure

Run is production failback. Drill restores then tears down. Assure is a policy-gated drill (QGA/HTTP/RTO) that feeds Assurance and Compliance.

Verification

Plans become VERIFIED after a successful readiness Check. Some installs require verification before Run. Assure now can still run while unverified.

DR mode

DR locations keep source VMID, MAC, and UUID. Overwrite only reclaims guests previously restored by this tool — foreign VMs are never deleted.

OpenClaw / agent skills
